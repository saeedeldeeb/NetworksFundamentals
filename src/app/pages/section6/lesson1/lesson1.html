Protocols Overview

High-level overview of common protocols — each built on the foundational layers we've already covered

Lesson 01

Introduction

Now that you understand IP, TCP, and UDP, you can see how every higher-level protocol is just a set of rules for formatting data that rides on those foundations. This section is a map of the landscape — enough to know what each protocol does and where it fits.

The Protocol Stack

Every protocol you use daily sits on top of the layers below it. Protocols don't reinvent the wheel — they delegate routing to IP, reliability to TCP, and speed to UDP.

Common Protocols and Their Transport

Protocol Transport Why?
HTTP/1.1, HTTP/2 TCP Needs reliability and ordering
HTTP/3 QUIC (UDP) Avoids TCP head-of-line blocking
DNS UDP Small queries, speed matters
SSH TCP Reliable encrypted tunnel
TLS TCP Encryption layer, protocol-agnostic
WebSocket TCP Persistent bidirectional connection
QUIC UDP Builds its own reliability, avoids TCP issues

How to Reason About Any Protocol

1
Needs reliability?

Probably uses TCP — or QUIC, which reimplements TCP-like guarantees on UDP.

2
Speed matters more than reliability?

Probably uses UDP — DNS queries, video streaming, gaming protocols.

3
Needs encryption?

TLS is somewhere in the stack. HTTPS = HTTP + TLS. Even QUIC has built-in encryption.

4
Remember the overhead budget.

Every layer adds headers. TCP (20 B) + IP (20 B) + TLS + your protocol's own header — it all adds up on top of the 8-byte UDP or 20-byte TCP base you already know.

Why brief overviews? Each protocol here deserves hours of deep-dive content — rich history, complex specs, security considerations. This section provides honorable mentions: enough to understand what each protocol does and where it fits, so you can confidently talk about the networking stack and know where to dig deeper.
Key insight: Once you understand the transport layer (TCP/UDP) and network layer (IP), every new protocol becomes easier to learn. You already know the foundations they build on. Each protocol is just a set of rules for formatting and interpreting the data that rides on those segments and packets.
