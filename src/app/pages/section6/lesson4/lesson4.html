Lesson 04

HTTPS, Certificates & Trust Chains

TLS encrypts the connection — but how does your browser know it's actually talking to google.com and not an impostor? That's the job of certificates and the trust chain. It's one of the most elegant systems in networking, and one of the most breakable.

What HTTPS Really Means

HTTPS = HTTP + TLS. But encryption only goes to the first destination. If you're using a CDN like Cloudflare, your traffic is decrypted at the CDN edge, inspected and cached, then re-encrypted to the backend. The CDN sees your plaintext request — by design. HTTPS doesn't mean end-to-end privacy across the entire path.

Two Uses of Asymmetric Encryption

Encryption — Proving the Recipient
How Encrypt with public key → only private key owner can decrypt
Use Send a secret only the intended recipient can read
Signatures — Proving the Sender
How Sign with private key → anyone with public key can verify
Use Prove the message came from you and wasn't tampered with

Certificates use signatures. A Certificate Authority (CA) signs your certificate with their private key. Anyone can verify that signature using the CA's public key — proving the cert is genuine and hasn't been modified.

What Is a Certificate?

An X.509 certificate is a public key with metadata attached, signed by someone the browser already trusts:

Field Contents
Subject Who this cert belongs to (domain / org)
SAN Subject Alternative Names — all valid domains
Issuer Who signed this cert (the CA)
Validity Not-before / not-after dates
Public Key The server's actual public key
Signature Hash of all the above, encrypted with the issuer's private key

Certificate Chain Verification

No CA signs a leaf certificate directly with the root — they use an intermediate CA. This limits exposure: the root private key stays offline, and only the intermediate key is used day-to-day. Watch the browser walk the chain:

Self-Signed vs CA-Signed

Type Characteristics
Self-Signed Signed with your own private key — free, instant, but browsers show a warning. Fine for internal/dev use.
CA-Signed CA verifies you own the domain, then signs. Browsers trust it. Required for production. Let's Encrypt is free.

Key insight: Certificates are the foundation of internet trust. The entire system depends on three things: (1) keeping private keys private, (2) trusting a small set of root CAs pre-installed in your OS, and (3) correctly verifying the chain. When any of these break — Heartbleed leaking private keys, a CA getting compromised, or a government installing their own root CA — the whole security model collapses.
