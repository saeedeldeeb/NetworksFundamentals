Lesson 02

MSS, MTU & PMTUD

Every byte you send must fit inside an Ethernet frame. The frame size sets a hard ceiling for everything above it — and when you understand that ceiling, you can design data flows that hit it perfectly instead of fragmenting across multiple frames.

The Frame Breakdown

An Ethernet frame carries an IP packet, which carries a TCP segment, which carries your application data. Each layer adds its own header — and those headers eat into the space available for actual data. Watch the numbers reveal themselves:

MTU vs MSS — What Each One Is

Concept Layer Definition
MTU
Maximum Transmission Unit L2 — Data Link Max IP packet size the link can carry. Ethernet default = 1500B. A property of the network interface.
MSS
Maximum Segment Size L4 — Transport Max TCP payload per segment = MTU − IP header (20B) − TCP header (20B) = 1460B. Negotiated during TCP handshake.

The Magic Number: 1460

1460 bytes is the standard MSS — the largest chunk of application data that fits in a single TCP segment without fragmentation. If your data is ≤1460 bytes, it travels in one segment: one network operation, minimum latency, minimum overhead. Every byte over 1460 forces a second segment — adding another 40 bytes of IP+TCP header tax on top of the extra data.
1
HTTP responses under 1460B ship in one segment

Small JSON APIs, health check endpoints, short HTML — design for this and you minimize round-trip latency.

2
Compress client-side before sending

gzip or brotli a 3KB payload down to <1460B and you've eliminated a segment — and the overhead that comes with it.

3
7 segments = 280 bytes wasted on headers alone

Every IP+TCP header costs 40 bytes. Seven segments to send 10KB of data pays 280B just for headers. Fewer segments = less tax.

Jumbo Frames

Some networks — particularly private cloud infrastructure — use jumbo frames with an MTU of 9000 bytes, giving an MSS of 8960B. More data per frame means fewer frames, less header overhead, and higher throughput. But this only works when every hop on the path supports the larger MTU.

Frame Size Pros Cons
Standard
MTU = 1500 Works everywhere on the internet More frames for large transfers, higher header overhead
Jumbo
MTU = 9000 Fewer frames, less overhead, great for bulk transfers Any bit flip corrupts a 9KB packet. All hops must agree. Not for the internet.
AWS, GCP, Azure likely use jumbo frames internally between their own machines — they own every hop in the path and run stable hardware. You benefit from this when your EC2 instances talk to RDS within the same VPC, even without configuring anything.

IP Fragmentation — What Happens When the Packet Doesn't Fit

If an IP packet is larger than the MTU of an intermediate link and the Don't Fragment (DF) flag is not set, the router splits it into multiple fragments. The destination reassembles them. This sounds fine — until you realize the costs:

Problem Impact
Reassembly overhead at destination CPU work to reconstruct the original packet
One lost fragment = retransmit entire packet No partial reassembly — everything must arrive
Fragmentation-based attacks Exploits use overlapping fragments to bypass firewalls
Modern TCP avoids fragmentation entirely Sets DF flag + uses PMTUD to stay within path MTU

Path MTU Discovery (PMTUD)

Your client may have an MTU of 9000, but a router somewhere in the middle might only handle 512-byte packets. PMTUD is the mechanism TCP uses to automatically discover the smallest MTU across the entire path — so it can size its segments to fit without fragmentation. Watch the discovery in action:

Jumbo Frame Configuration

Summary

Concept Layer Default
MTU L2 1500B — max IP packet carried by one Ethernet frame
MSS L4 1460B — TCP payload = MTU − 40B headers
PMTUD L3/ICMP Auto-discovers lowest MTU across path. Requires ICMP not be blocked by firewalls.
Key insight: 1460 is the sweet spot for internet TCP — one segment, zero fragmentation, minimum overhead. Every extra segment adds 40 bytes of header tax. Design your payloads with awareness of this limit: compress aggressively, batch wisely, and let PMTUD handle the rest. When PMTUD breaks (blocked ICMP), connections mysteriously stall — always keep ICMP open on your firewalls.
